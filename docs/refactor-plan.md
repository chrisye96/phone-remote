# 重构计划

状态：进行中。第 0 到 4 步和第 6 步已完成。第 5 步（Mac）需要在 Mac 上测试。

## 目标

1. 代码按职责拆开，不再是一个 `remote.py` 加一个 `index.html`。
2. Windows 和 Mac 各有一套针对本系统的实现，功能尽量一致。
3. 运行时没有黑色命令行窗口，也不再挂一个 PowerShell 子进程。
4. 重构期间每一步结束后程序都能正常使用，随时可以停下。

## 技术选型

**电脑端：继续用 Python，但引入少量依赖，最后打包成免安装的程序。**

| 方案 | 结论 | 理由 |
|---|---|---|
| Python + 平台库 | 采用 | 现有逻辑都在 Python 上验证过，拆分风险最低。Windows 用 `winrt` 库直接调系统媒体接口，去掉 PowerShell；Mac 用 `pyobjc` 直接调系统接口，能做到和 Windows 接近的功能。打包后双击运行，没有黑窗口。 |
| Java | 不采用 | 自带的 `Robot` 能跨平台模拟按键鼠标，也有托盘图标，这是优点。但它发不了音量键和媒体键，读不了播放状态和音量，列不了窗口，这些都要再接原生库，Windows 读播放状态多半还得留着 PowerShell。还要求装 Java 或捆绑一个 40 MB 以上的运行时。 |
| Rust | 备选 | 单文件、无依赖、原生接口最干净。但等于全部重写，Mac 版必须在 Mac 上编译，而 Mac 端目前无法在开发机上测试，风险最大。等功能稳定后再考虑。 |
| Go、C# | 不采用 | Go 调 Windows 媒体接口困难；C# 在 Mac 上支持弱，会变成两套代码。 |

**手机页面：拆成多个原生文件**（已确认）。HTML、CSS、JS 分开，JS 用浏览器原生模块，不引入框架，不需要构建。

## 目标结构

```
phone-remote/
  pyproject.toml              依赖和入口声明
  src/phone_remote/
    __main__.py               入口：读配置、启动服务器和托盘
    config.py                 端口、配对码、文件路径
    server.py                 HTTP 路由、配对校验、静态文件
    actions.py                指令分发和参数校验
    keys.py                   按键名表、组合键解析
    timer.py                  定时暂停
    pairing.py                二维码页面
    tray.py                   托盘图标和菜单
    selftest.py               自检：逐项检查本机能力并打印报告
    platforms/
      base.py                 统一接口：输入、窗口、媒体、音量
      windows/                input.py  windows.py  media.py  audio.py
      macos/                  input.py  windows.py  media.py  audio.py
  web/
    index.html
    css/                      base.css  screens.css
    js/                       main.js  api.js  nav.js  buttons.js  touchpad.js
                              media.js  text.js  windows.js
  tests/                      不依赖真实系统的自动测试
  scripts/                    打包脚本
  docs/
```

平台差异全部收在 `platforms/` 里，其他代码只调用 `base.py` 定义的接口。

## Windows 与 Mac 功能对照

| 功能 | Windows 现状 | Mac 现状 | Mac 目标做法 |
|---|---|---|---|
| 按键、组合键、鼠标、滚动、文字输入 | 可用 | 已写，未测 | 改用 pyobjc 的 Quartz 接口，逐项实测 |
| 系统音量加减、静音、音量数值 | 可用 | 已写，未测 | 保持 AppleScript，实测 |
| 媒体播放键 | 可用 | 退化成空格 | 用系统级媒体键事件，不再依赖焦点 |
| 窗口列表和切换 | 按窗口 | 按应用 | 用辅助功能接口列出每个窗口并切换 |
| 窗口最大化、最小化、换屏幕 | 可用 | 部分 | 用辅助功能接口移动和缩放窗口 |
| 播放状态、标题、进度、跳转 | 可用，有延迟 | 无 | 见下方"风险" |
| 托盘图标、无窗口运行 | 无 | 无 | 两边都用菜单栏或托盘图标 |
| 免安装运行 | 需要装 Python | 需要装 Python | Windows 出 exe，Mac 出 app |

## 步骤

每一步都在自己的 `feature/*` 分支上做，合进 `dev`，实测通过后再进下一步。

### 第 0 步：备份原版（已完成）

- 分支 `legacy/v0.2.0-single-file` 和标签 `v0.2.0` 指向重构前的版本，之后不再改动。
- 压缩包 `C:\Users\Chris\source\repos\phone-remote-v0.2.0-backup.zip` 存在仓库外面。
- 恢复方法：解压压缩包，或 `git checkout legacy/v0.2.0-single-file`。

### 第 1 步：先加测试（已完成）

在动代码之前，给不依赖真实系统的逻辑写自动测试：组合键解析、指令参数校验、配对码校验、非法请求被拒绝。用一个假的平台实现代替真实的按键和鼠标。

验收：测试全部通过，`remote.py` 本身不改。

### 第 2 步：拆分电脑端代码（已完成）

把 `remote.py` 按"目标结构"搬进 `src/phone_remote/`，只搬不改逻辑。定义 `platforms/base.py` 的统一接口，Windows 和 Mac 各自实现。PowerShell 子进程这一步原样保留。启动方式变成 `python -m phone_remote`，`start-windows.bat` 同步修改。

验收：第 1 步的测试通过；手机上四个页面的功能和 v0.2.0 表现一致。

### 第 3 步：拆分手机页面（已完成）

把 `index.html` 拆成 HTML、CSS 和若干 JS 模块。服务器改为从 `web/` 目录提供静态文件，只允许访问这个目录内的文件。

验收：手机上外观和行为与拆分前一致；浏览器控制台没有报错。

### 第 4 步：Windows 去掉 PowerShell（已完成）

用 `winrt` 库在进程内读取播放状态、标题、进度并执行跳转，用系统音频接口读音量。删除 PowerShell 脚本。顺便重新测量状态上报的延迟，看原生调用是否比现在的 10 秒好。

验收：任务管理器里不再有 powershell 进程；播放状态、进度条、跳转、音量数值都正常。

### 第 5 步：Mac 实现补齐

按对照表逐项实现 Mac 端，并加入 `python -m phone_remote --selftest` 自检命令：它逐项测试按键、鼠标、音量、窗口、媒体，打印一份结果报告。

这一步开发机上无法测试，需要你在 Mac 上运行自检命令并把输出发回来，按结果修正。预计要来回几轮。

验收：自检报告全部通过，或未通过的项目有明确原因并记录在文档里。

### 第 6 步：托盘图标，去掉黑窗口（已完成）

程序启动后只在托盘（Mac 是菜单栏）显示一个图标，菜单里有：显示二维码、开机自动启动、退出。二维码改为本地生成，不再依赖外网。

验收：双击启动后没有任何窗口，托盘图标可用；重启电脑后按设置自动运行。

### 第 7 步：打包

用 PyInstaller 生成 Windows 的单个 exe；Mac 生成 app，这样辅助功能权限授给它自己，而不是授给"终端"。

验收：在没有装 Python 的环境里能双击运行。

### 第 8 步：收尾

删除旧的 `remote.py`、`index.html`、`start-windows.bat`，更新 README，合并到 `main`，打标签 `v0.3.0`。

## 风险

- **Mac 无法在开发机上测试。** 这是整个计划里最大的不确定性，第 5 步的进度取决于你在 Mac 上跑自检的来回次数。
- **Mac 读取播放状态没有公开接口。** 苹果从 macOS 15.4 起限制了原来常用的私有接口。备选做法是通过 AppleScript 让浏览器执行脚本直接读视频状态，这还能顺带实现倍速，但需要在浏览器里打开一个开发者选项。具体走哪条路要在第 5 步根据你的 macOS 版本试验后决定，有可能做不到和 Windows 完全一致。
- **依赖库对 Python 3.14 的支持。** `winrt` 和 `pystray` 在包索引里都有，但还没在本机装过，第 4 步和第 6 步开始时先验证。
- **B 站倍速。** 重构不解决这个问题，Windows 上仍然没有不装扩展的办法。

## 执行中的调整

- 第 1 到 3 步是一起做的：测试直接针对拆分后的模块写，而不是先给旧的单文件写一遍再改。旧文件已删除，原版在 `legacy/v0.2.0-single-file` 分支和压缩包里。
- 手机页面放在 `src/phone_remote/web/` 里而不是仓库顶层，这样打包时它跟着程序一起走。CSS 只有不到一百行，暂时是一个文件。
- 测试用 Python 自带的 unittest，不需要额外安装。
- 第 4 步：播放状态和进度用 `winrt` 库读取，音量直接调系统音频接口，没有引入额外的库。程序装在仓库里的 `.venv` 虚拟环境中，不影响系统的 Python。没装 `winrt` 时程序照常运行，只是没有播放状态和进度。
- 第 4 步里原本想重新测量状态上报的延迟，但测试时视频所在的标签页不是 Chrome 的当前标签页，后台标签页会被浏览器限速，所以之前测到的“晚 10 秒”和“暂停时跳转不可靠”可能偏悲观，需要在正常观看时再确认。
- 新增功能开关（见 README），为以后区分免费和付费功能做准备。
- 配对码和配置文件搬到了用户数据目录（Windows 上是 `%APPDATA%\PhoneRemote`），旧的配对码会自动沿用，不用重新扫码。

## 浏览器支持目标

要求支持 Safari、Chrome、Firefox，其中 Chrome 和 Firefox 两个系统都要支持。

| | 按键、鼠标、音量、窗口 | 播放状态、进度、跳转 |
|---|---|---|
| Windows + Chrome / Edge / Firefox | 支持 | 支持（走系统媒体接口，三个浏览器都会上报） |
| Mac + Safari / Chrome | 支持 | 预计可以，走浏览器脚本接口，需在浏览器里打开一个开发者选项 |
| Mac + Firefox | 支持 | 大概率做不到：Firefox 不提供脚本接口。第 5 步里再试系统级的读取办法，不保证成功 |

Mac 系统版本按最近两三个大版本处理，也就是都在苹果收紧接口之后，所以不指望旧的私有接口。

## 以后如果要收费

不属于这次重构，但有几件事会影响后面的做法，先记在这里：

- Windows 未签名的程序会被系统拦一下，需要代码签名证书，或者上架微软商店。
- Mac 必须加入苹果开发者计划做公证，否则打不开；这类软件要模拟按键，进不了 Mac App Store，只能官网直接卖。
- 需要加授权码校验、试用期、自动更新。
- 用到的库里 `pystray` 是 LGPL 协议，可以用于收费软件，但要保留它的声明；其余都是宽松协议。
